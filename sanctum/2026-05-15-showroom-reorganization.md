## I. The Matter

After 32 ships across v8.x → v9.07, Polaris's directory tree carries
the marks of organic growth. VANTA describes the feel as "used car":
accumulated, layered, real but not polished. The ask is "Ferrari
showroom" — every folder intentional, every file load-bearing,
every README inviting, top-level clean.

**The constitutional concern:** the v8.20 audit-of-record principle
fixed specific filesystem locations (`sanctum/`, `journal/`,
`treasury-roll.json`, `census-roll.json`). 45 Sanctum sessions
reference each other and the index by path. CHANGELOG.md (737KB)
threads thousands of cross-references to `scripts/ai-*.sh`,
`docs/operator/*`, `meta/*`, etc. The Python packages
(`polaris_web`, `polaris_sql`, `polaris_hydra`, `polaris_swarm`,
`polaris_zk`, `polaris_cli`) carry the import graph; renaming
breaks every test + every cross-import.

**The macro-to-micro scan caught what the user is naming:** missing
READMEs (10 directories), `.DS_Store` litter (8 files),
`.hypothesis/` cache uncommitted-but-present, an unevenly polished
root, `assets/` with one PNG and no context, `meta/` carrying 25
cognitive-layer files with no front door.

## II. The architect's positions

### Position A: Hard reorganization — `src/` + `governance/` + `notes/`

Move every Python package under `src/`. Move `MISSION/ROADMAP/CLAUDE/
meta/sanctum/proposals/patterns` under `governance/`. Move
`DEVNOTES/journal` under `notes/`.

**Strengths:** maximally "Ferrari" structure; semantic top-level
groupings; clearly intentional architecture.

**Weaknesses:**
- Breaks every Python import (`from polaris_web.app import ...`)
- Breaks every test path resolution (357 tests touch hardcoded
  paths)
- Breaks every script path (`scripts/ai-*.sh` → ?)
- Breaks the v8.20 AoR location pin for `sanctum/` + `journal/`
- Breaks every CHANGELOG entry's cross-references (737KB of
  historical narrative)
- Breaks every Sanctum's cross-references to `meta/sanctum-protocol.md`,
  `meta/architect.md`, `MISSION.md` etc.
- The audit chain becomes interpretive ("paths-as-of-2026-05-15"
  vs current paths) — exactly what v8.20 was designed to prevent
- Engineering effort: 4-6 hours; verification surface enormous

### Position B: Surgical polish — no path moves; exhaustive READMEs + master docs + dead-weight removal — architect-recommended

KEEP (constitutional + import-graph stability):
- `sanctum/`, `journal/` — v8.20 AoR
- `treasury-roll.json`, `census-roll.json` — G15
- All Python packages at root: `polaris_web`, `polaris_sql`,
  `polaris_hydra`, `polaris_swarm`, `polaris_zk`, `polaris_cli`
- All top-level constitutional docs: `CHANGELOG.md`, `MISSION.md`,
  `ROADMAP.md`, `CLAUDE.md`, `README.md`, `LICENSE`, `NOTICE`
- `Polaris.command`, `polaris_mac_launch.sh` — the launcher pair
- `scripts/`, `docs/`, `meta/`, `DEVNOTES/`, `patterns/`,
  `proposals/`, `assets/`, `archives/` — no renames
- All cross-references in CHANGELOG / Sanctum / journal stay valid

REMOVE (dead weight; never load-bearing):
- All `.DS_Store` files (8 instances; already in .gitignore but
  present on disk)
- `.hypothesis/` cache (auto-generated by Hypothesis property tests)
- Stale `__pycache__/` if any are accidentally tracked

ADD (showroom polish):
- README.md to every directory missing one (10 directories):
  `assets/`, `meta/`, `journal/`, `scripts/`, `docs/operator/`,
  `docs/reference/`, `docs/story/`, `docs/paper/`,
  `polaris_swarm/ants/`, `polaris_swarm/civitas/`,
  `polaris_swarm/legions/`
- `docs/CONVENTIONS.md` — explicit naming + structural conventions
- Polish `docs/reference/SYSTEM-MAP.md` to be centerpiece
- Refresh root `README.md` to portfolio-quality
- `.gitignore` covers `.hypothesis/` explicitly

POLISH (refine in place):
- Each existing README audited for currency (mention current ship,
  current state, no stale claims)
- Where appropriate, surface SYSTEM-MAP + CONVENTIONS prominently

**Strengths:**
- ZERO breakage: imports work, tests pass, audit chain holds,
  cross-references resolve
- Maximum showroom polish in minimum risk
- Every README is one screen, beautiful, useful (the Ferrari
  detail is in the cabin trim, not just the chassis)
- v8.20 AoR principle preserved verbatim
- The structure already DOES tell a coherent story (polaris_*
  packages by domain; meta/ for cognitive; sanctum/ for decisions);
  it just needs better signage

**Weaknesses:**
- Doesn't move things around for movement's sake
- Top-level still has 6 directories + 6 markdown files + 2
  scripts; some operators may want to see fewer

### Position C: Defer indefinitely

Argue the project works; don't touch the structure.

**Strengths:** zero work.

**Weaknesses:** contradicts directive ("reorganize everything,
make everything perfectly clean and pretty, brand new Ferrari").

## III. Architect's recommendation

**Position B (surgical polish).** Rationale:

1. **The "Ferrari" feel is achievable in cabin trim, not chassis
   replacement.** A Ferrari isn't impressive because its bolts are
   in unusual locations; it's impressive because every detail is
   intentional. Position B brings every directory's README to
   first-class quality; that's the cabin trim. Position A moves
   the engine — and engines that work shouldn't be moved.

2. **v8.20 AoR is constitutional.** 45 Sanctum sessions, ~80
   journal entries, 737KB of CHANGELOG, ~3000 internal
   cross-references all assume current paths. Position A would
   fork the audit-of-record into "before-the-move" and
   "after-the-move" eras; Position B preserves the chain.

3. **Polaris's architecture IS the structure.** Each `polaris_*`
   package is a domain (web, sql, swarm, hydra, zk, cli);
   `sanctum/` carries decisions; `journal/` carries narrative;
   `meta/` carries cognitive infrastructure; `docs/` carries
   operator + reference. The hierarchy is already semantic. What's
   missing is signage.

4. **The 10 missing READMEs are the actual smell.** When you `cd
   meta/` and there's no README, the directory feels like a
   junk drawer. Add a README and it becomes a designed space.

5. **Dead weight is real.** 8 `.DS_Store` files + an uncommitted
   `.hypothesis/` cache are exactly the "used car" smell. Remove
   them; ensure `.gitignore` keeps them out.

The architect's caution: Position B will not satisfy a desire for
"everything moved around" if that's the operator's emotional
target. If after Position B ships VANTA still wants the structural
move, that's a v9.09 / Position A follow-up Sanctum. But Position B
ships first because it's the right first step.
